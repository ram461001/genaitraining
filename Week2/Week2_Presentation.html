The Problem with LLMs

Knowledge Cutoff

LLMs are trained on data up to a fixed date. They don't know about recent events or your private data.

Hallucination

When LLMs don't know something, they tend to make up plausible-sounding but wrong answers.

No Private Data

LLMs cannot access your company's internal documents, databases, or real-time information.

# Without RAG
llm.invoke('What is Acme Corp refund policy?')

# Output:
"I don't have specific information
about Acme Corp's refund policy.
You should check their website..."

# ❌ Unhelpful — model doesn't know
The Gap: Your documents exist, but the LLM can't see them.

Chunking

from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(

chunks = splitter.split_documents(docs)

2.3 — Embeddings

An embedding converts text into a vector of numbers that captures its meaning.

'I love pizza' → [0.12, -0.45, 0.88, ...]
'Pizza is my favourite' → [0.10, -0.47, 0.85, ...] ← close!
'Stock market crashed' → [-0.71, 0.33, -0.12, ...] ← far

Cosine Similarity — Semantic Search

import numpy as np

def cosine_similarity(v1, v2):
    return np.dot(v1, v2) / (
        np.linalg.norm(v1) * np.linalg.norm(v2)
    )

2.4 — Vector Stores (Chroma)

A vector store saves embeddings and lets you search them by similarity. We use Chroma — local, no setup needed.

from langchain_community.vectorstores import Chroma

# Create + store embeddings
vectorstore = Chroma.from_documents(
    documents=docs,
    embedding=embeddings,
    persist_directory='./chroma_db'  # save to disk
)

# Search by similarity
results = vectorstore.similarity_search(
    'Can I work from home?', k=3
)

# Use as a retriever in chains
retriever = vectorstore.as_retriever(
    search_kwargs={'k': 3}
)

2.6 — Conversational RAG

Basic RAG answers one question at a time. Conversational RAG handles follow-up questions using chat history.

Problem:
User: "How many leave days?"
Bot: "20 days."
User: "What about sick leave?" ← needs context!
Bot: ??? (doesn't know what "what about" refers to)
Solution — Rephrase Step:
"What about sick leave?"
↓ rephrase using history
"What is the company's policy on sick leave?"
↓ retrieve + answer correctly 
# Two-prompt architecture

# 1. Rephrase follow-up → standalone
rephrase_prompt = ChatPromptTemplate.from_messages([
    ('system', 'Rephrase as standalone question'),
    MessagesPlaceholder('chat_history'),
    ('human', '{question}'),
])

# 2. Answer using retrieved context
answer_prompt = ChatPromptTemplate.from_template("""
Context: {context}
Question: {question}
Answer:""")

2.7 — Advanced Retrieval

Basic similarity search has weaknesses. Three techniques improve it significantly.

MMR — Maximal Marginal Relevance

Avoids returning redundant chunks. Balances relevance and diversity.

retriever = vectorstore.as_retriever(
    search_type='mmr',
    search_kwargs={
        'k': 3, 'fetch_k': 8,
        'lambda_mult': 0.5  # 0=diversity, 1=relevance
    }
)

LLM Reranking

After retrieving 6 candidates, ask LLM to score each 0–10. Keep top 3.

Hybrid Search — BM25 + Semantic

BM25 catches exact keyword matches. Semantic catches meaning. Combine both.

from langchain.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever

hybrid = EnsembleRetriever(
    retrievers=[bm25_retriever, semantic_retriever],
    weights=[0.5, 0.5]
)

2.8 — RAG Evaluation

How do you know your RAG pipeline is actually working? Measure 4 key metrics.

MetricQuestion it answers
FaithfulnessIs the answer grounded in context? (no hallucination)
Answer RelevanceDoes the answer address the question?
Context RecallDid we retrieve the right chunks?
Context PrecisionAre the retrieved chunks useful?
Evaluation loop:
Build RAG → Evaluate → Identify weak metric → Fix → Re-evaluate

LLM-as-Judge (works with Ollama)
